## A부 — 계획서 작성과 승인

### A1. 작성

**출장 신청(Request Plan)** 탭에서 **Chat** 을 누릅니다.

> **해외출장 일반으로 출장 계획 만들어줘. 2026-11-10부터 2026-11-12까지 오사카로 가고, 출장자는 김충북이야. 제목은 오사카 협력사 방문, 출발지는 인천공항이야**

양식을 채운 뒤 동행자를 묻습니다. **동행자를 넣어야** 뒤의 식비 테스트가 의미를 가집니다.

> **김도하도 같이 갑니다**

이어서 경로, 교통수단, 목적지 상세를 묻습니다.

> **둘 다 비즈플레이에서 출발해서 티엑스알로보틱스(본사)로 갔다가 비즈플레이로 돌아옵니다**

> **비행기로 이동합니다**

> **없습니다**

마지막으로 결재선:

> **김도하 결재로 제출해줘**

**Done ✓ — save now** 를 누르면 "Plan draft saved to BizPlay." 가 보입니다.

> 해외 출장인데도 경로 선택지에 국내 지점만 나옵니다. 테넌트의 지점 마스터가 그렇게 되어 있는 것이지
> 흐름의 결함이 아닙니다. 아무거나 고르면 됩니다.

### A2. 승인

이 시점의 계획서는 DRAFTED 라 아직 정산할 수 없습니다.

1. 우측 상단에서 **Traveler** → **Admin** 으로 전환합니다.
2. **출장 승인(Approve Plan)** 탭에서 해당 문서를 찾아 **Approve** 를 누릅니다.
3. 다시 **Traveler** 로 돌아옵니다.

문서번호를 적어 두세요. 테스트 시에는 `2026-출장계획서-1696` 이었습니다.

## B부 — 정산

**지출 보고(Expense Report)** 탭 → **Settle in Chat**.

### B1. 이전 세션 정리

이전 실행의 증빙이 남아 있으면 먼저 **Start over with another trip** 을 누릅니다.

### B2. 문서번호로 계획서 지정

> **2026-출장계획서-1696**

계획서를 찾아 불러오고 경비 항목 chips 가 나타나야 합니다.
**업데이트 6** — 채팅이 처음 띄운 목록에 없는 계획서라도 찾아냅니다.

### B3. 숙박비 증빙 시작

**숙박비** → **Other receipts (기타증빙)** → **Add manual expense** 순서로 누릅니다.

> ⚠️ 입력 폼이 함께 뜹니다. **반드시 하단 채팅창에 입력**하세요. 폼에 입력하면 진행되지 않습니다.

### B4. 호텔 입력

> **11월 10일부터 12일까지 오사카 호텔 400달러 2박, 스탠다드 룸**

미리보기에 가맹점 오사카 호텔, 400 USD, 원화 ₩529,136 이 보여야 합니다.
**Register** → **Register without an image** 를 누릅니다.

**실제 결과**

| 항목 | 값 |
|---|---|
| 규정 안내 | `한도 USD 100/일. 적용 조건: 평일 +10,000원` |
| 규정금액 | **₩284,568** |
| 카드의 외화금액 | 400 — 이건 **지출액**입니다. 규정금액 쪽에는 외화 표기가 없어야 합니다(**업데이트 3**) |
| 신청금액 | ₩284,568 — 규정금액으로 캡 |

₩284,568 이 **업데이트 4** 입니다. BizPlay 가 2일치 USD 100/일을 돌려주고, 각 일자를 환율 1,322.84 로
환산해 132,284 로 절사한 뒤 평일 조건 +10,000 을 더해 하루 142,284 가 됩니다.

### B5. 초과분할

답변 끝에서 초과를 알리고 분할 여부를 묻습니다. **업데이트 5** 입니다.

> **네, 분할해 주세요**

`Split done: 오사카 호텔 policy ₩284,568 / own expense ₩244,568` 과 함께 카드에 **2행**이 생기고,
각각 `policy row` / `own expense` 로 표시되며, 합계는 ₩529,136 · 2 item(s) 로 **한 번만** 계산됩니다.

### B6. 식비 추가

> **식비**

**업데이트 7** 입니다. 반드시 **어떤 카드를 조회할지** 물어야 합니다.
여기서 정산 요약이 나오면 finish 게이트가 회귀한 것입니다.

**Other receipts (기타증빙)** → **Add manual expense**:

> **11월 11일 점심 식사 오사카 식당 20000원**

미리보기에 `which meal: LUNCH` 가 이미 들어 있어야 합니다(문장에서 가져옴, **업데이트 1**).
chips 를 보려면 끼니를 빼고 입력하세요. 아침/점심/저녁/간식/야식/식사/기타 를 묻습니다.

**Register** → **Register without an image**.

**실제 결과**

| 항목 | 값 |
|---|---|
| 규정 안내 | `정액 ₩129,044/일 **(동행 1명 포함, 2인 합산)**` |
| 규정금액 | ₩129,044 |
| 초과 | 없음. ₩20,000 은 한도 훨씬 아래 |

**업데이트 2** 입니다. 계획서에 김도하가 없었다면 한도는 절반인 ₩64,522 였습니다.

### B7. 상신

**Done — no more expenses** → **Submit to BizPlay** → **File it as it is**.

정산서 번호가 나옵니다. 테스트 시에는 `2026-출장정산서-1698` 이었습니다.

## BizPlay 쪽에서 확인

상신된 문서에는 분할된 숙박 2행과 식비 1행, 총 3행이 있어야 합니다.

```bash
curl -s "https://cloud-dev.bizplay.biz/api/v2/approval/bstr/plan/152109/pre-receipts/form?corpUserId=30447" \
  -H "Authorization: Bearer $BIZPLAY_DEV_TOKEN" -H "accept: */*" -H "X-RR-MODE: NONE"
```

`152109` 는 본인 계획서의 approvalId 로 바꾸세요. 실제 반환값:

| 증빙 | 용도 | 분할 | 승인금액 | 규정금액 | 신청금액 |
|---|---|---|---|---|---|
| 343420 | ROOM | EXCESS order 0, excessOver false | 529,136 | 284,568 | 284,568 |
| 343420 | ROOM | EXCESS order 1, excessOver true | 529,136 | 284,568 | 244,568 |
| 343421 | FOOD | 없음 | 20,000 | 129,044 | 20,000 |

숙박 2행은 **같은 receiptId** 를 쓰고, 지출액과 규정금액은 그대로 두며 **신청금액만 나눕니다.**
두 신청금액의 합은 원래 지출액과 같습니다.
